# Interview Notes

### 프로젝트를 한 문장으로 설명해보세요.
실제 차량 CAN 로그를 Window 단위로 분석해 Normal/DoS/Fuzzy/Gear/RPM 패턴을 ML로 분류하고, 이상 구간을 엔지니어용 Incident Report로 자동 정리하는 AX MVP입니다.

### 왜 Window 기반인가요?
CAN 공격은 메시지 한 줄보다 일정 구간의 전송 빈도, ID 분포, 반복 주기 변화가 중요하기 때문입니다.

### 왜 Random Forest인가요?
표 형태의 통계 feature에 적용하기 쉽고 비선형 관계를 처리하며, 빠르게 학습할 수 있고 feature importance도 확인할 수 있기 때문입니다. Logistic Regression을 baseline으로 비교했습니다.

### 왜 기본 Window를 200으로 선택했나요?
100은 실제 샘플 공격유형 판별이 80%로 떨어졌고, 500은 실험상 완벽한 점수를 보였지만 한 Window가 커져 이상 위치의 시간적 해상도가 낮아집니다. 200은 Macro F1 0.9974와 100% sample-type accuracy를 유지하면서 500보다 세밀한 구간 분석이 가능해 기본값으로 선택했습니다.

### F1이 너무 높은 것 아닌가요?
현재 결과는 동일 HCRL 데이터셋 내부 평가입니다. 공격이 특정 ID/주기 패턴을 갖고 있어 점수가 높게 나올 수 있으며, 새로운 차량이나 공격으로 일반화된다고 주장하지 않습니다.

### LLM은 어디에 사용하나요?
공격 판정에는 사용하지 않습니다. ML 결과를 자연어 Incident Report로 정리하는 선택적 보조 역할만 하며, Ollama가 없어도 deterministic report가 동작합니다.

### AX라고 보는 이유는?
로그 확인 → 이상 구간 선별 → 초기 분석 정리 → 보고서 작성이라는 반복 업무를 로그 입력 → 자동 탐지 → 구조화 → 보고서 생성 → 사람 승인 흐름으로 재설계했기 때문입니다.
